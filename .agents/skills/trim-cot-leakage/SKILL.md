# Trim CoT Leakage (会话视角与思维链泄漏清洗)

本规则用于约束 Agent 生成的代码注释、Commit 信息、PR 描述与技术文档，确保所有输出**站在仓库 HEAD 的视角**，彻底清除单次会话的临时脚手架。

## 1. 核心硬判据

> **一个只检出当前分支 HEAD、脱离本次对话和 PR 历史的读者（人类或新 Agent），能否独立理解并验证每一个术语和论断？**

如果不能，必须将事实重构为声明式 HEAD 状态，剥离会话脚手架；没有事实价值的纯会话叙述，整句删除。

## 2. 猎杀目标与违禁模式

### A. 禁止死掉的设计会话引用 (Dead Citations)
- ❌ **严禁出现**：`(decision 7)`、`阶段标签 (T4/W3)`、`设计台账`、`内部审计码`、`按照第 3 版讨论`
- ✅ **重构方式**：直接陈述该约束本身，或引用持久化的文档链接（如 `[agent-notes-design.md](docs/agent-notes-design.md)`）。

### B. 禁止会话代词与时序指涉 (Session Chronology)
- ❌ **严禁出现**：`如上文所述`、`正如我们所见`、`在这个 PR 中我们修改了`、`上一轮尝试失败了，现在改成`、`不再使用旧的 X`
- ✅ **重构方式**：直接描述模块当前职责。例如将“本 PR 不再使用旧的轮询方式，改为事件驱动”重写为：“采用事件驱动架构实现状态同步”。

### C. 禁止向审阅者解释的辩护性注释 (Reviewer Defense)
- ❌ **严禁出现**：`// safe cast because reviewer asked`、`// 审阅者确认了这里的并发安全`
- ✅ **重构方式**：将安全性证明体现在类型系统、函数前置断言（`assert!`）或模块的不变量（Invariant）说明中。

## 3. 执行准则与检查清单

在生成 PR 描述、Commit 消息、注释或技术文档前，逐项自检：
1. **带事实的陈述**：先把事实重述为 HEAD 独立成立的声明式状态，再剥离周围会话转录。
2. **纯会话叙述**：整句删除。
3. **悬垂引用**：不得出现不存在于代码库中的 issue/阶段编号。
4. **自解释性**：所有事实性陈述在当前提交的代码中完全成立且自解释。
