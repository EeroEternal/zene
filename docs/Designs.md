# Zene UI Design

根目录 [`DESIGN.md`](../DESIGN.md) 为入口。对照稿：[`docs/design/changes-and-checks.png`](./design/changes-and-checks.png)（变更与检查）。实现：`cloud/apps/web/`。

Zene Cloud Console 是面向开发者的 Agent 工程工作区：启动任务、观察执行、审查代码变更，并在关键节点人工接管。视觉参考 VS Code 的工作区结构、GNOME 的克制实用、以及 Git / CI 工具的工程感。不采用 SaaS 营销或 AI 产品风格。

核心体验：知道 Agent 在做什么、为什么这样做，也能在必要时接管。

## 视觉关键词

开发者优先、浅色工程界面、低饱和灰阶、结构清晰、代码优先、安静克制、可审查、可追踪、支持人工接管、减少装饰与线条。界面应接近可长期使用的开发工具，而不是营销站或传统后台。

## 色彩

颜色用来区分功能区域和状态，不作装饰。蓝色克制使用，不铺大面积品牌底。

```css
--color-bg: #F6F5F4;
--color-nav: #EBE9E7;
--color-surface: #FFFFFF;
--color-ink: #2E3436;
--color-muted: #687174;
--color-primary: #3584E4;
--color-accent: #E5A50A;
--color-warning-bg: #FFF5D6;
--color-success: #287A46;
--color-success-bg: #EAF4EC;
--color-error: #C01C28;
--color-error-bg: #FCEBEC;
--color-primary-soft: #EAF2FF;
```

| 角色 | 色值 | 用途 |
|------|------|------|
| 工作区背景 | `#F6F5F4` | 页面画布，避免纯白带来的商业感 |
| 导航 | `#EBE9E7` | 窄工具栏与项目树 |
| 主内容 | `#FFFFFF` | 任务、Diff、检查；靠背景差和轻阴影分区，少描边 |
| 主操作 | `#3584E4` | 选中项、运行中、主按钮、链接；不铺整区 |
| 等待 / 审批 | `#E5A50A` / `#FFF5D6` | 待批准、权限请求、高风险、需确认 |
| 成功 | `#287A46` / `#EAF4EC` | 检查通过、运行完成；必须配文字 |
| 失败 | `#C01C28` / `#FCEBEC` | 失败与阻断；必须说明原因 |
| 执行提示 | `#EAF2FF` | 当前步骤、变更摘要条 |

Auth / Login 仍用同一套 token。不要把对照稿里的深色终端块当成整页主题。

## 字体

界面：`Inter, sans-serif`。标题 22–24px / 600；区域标题 14–16px / 600；正文 13–14px / 400；导航 12–13px；状态 12px / 600；辅助 11–12px。标题不宜过大。

路径、文件名、命令、变量、日志、Diff、退出码、工具参数：等宽 `ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, "JetBrains Mono", monospace`，约 12px。关闭连字（避免 `://` 被吃掉）。

## 页面框架

工程工作区采用三栏：

```text
窄工具栏（~52px） | 项目 / 上下文导航（220–240px） | 主工作区
```

窄工具栏：产品标识、工作区首页、运行历史、设置。低存在感，简单线图标，选中用浅蓝底，不用大型品牌标。

项目导航像文件树，不像 SaaS 侧栏。展示当前 Agent / 仓库上下文：工作区概览、任务与计划、运行工作台、变更与检查、任务历史；分隔线以下为上下文、`AGENTS.md`、工具与权限。

主工作区承载任务描述、执行步骤、工具调用、文件、终端、Diff、检查与审批。内容优先，不做装饰模块。

Zene 现有页面对应关系：New Agent 是空态下的新建任务入口（居中 composer）；Run 对话流是运行工作台；CodePanel 是变更与检查；Settings 走工具栏设置。实现时按本规范的视觉与信息结构演进，不要继续用 Cursor 营销蓝或大面积文档站壳。

## 核心页面

### 工作区概览

回答：当前项目什么状态、哪个任务未完成、Agent 是否在等批准、下一步从哪继续。展示仓库与分支、未提交变更、运行状态、最近任务、环境、基础检查、工作区规则、待批准操作。不以欢迎区或 Hero 开场。

### 运行工作台

产品核心页。三类信息必须分开：意图（Agent 想做什么）、动作（实际执行的命令 / 工具）、证据（命中的文件、测试结果、退出码）。建议左侧步骤树、中间当前步骤、右侧运行上下文、底部可展开终端、审批区。默认摘要，不默认铺满日志。

### 变更与检查

审查代码影响，而不是只显示「任务完成」。变更文件树、+/- 行数、Diff、修改原因、关联步骤与测试、TypeScript / 单测 / Lint / 集成测试、批准记录。Diff 旁应能看到对应步骤、依据、关联测试和批准状态。对照稿见 [`docs/design/changes-and-checks.png`](./design/changes-and-checks.png)。

## 按钮

接近 GNOME / VS Code 工具按钮：圆角 4–6px，高度约 32px，文字优先，无胶囊形、无渐变、无浮夸阴影。主按钮同一屏不要大量重复。

主操作：`background #3584E4; color #FFFFFF; border-radius 5px`。用于新建任务、批准并继续、运行检查、开始运行、接受并标记已验证。

次操作：`background #E4E2E0; color #2E3436; border-radius 5px`。用于暂停、停止、查看日志、复制路径、打开终端。

危险操作不用大面积鲜红按钮：红字或浅红底，动作写清楚（停止运行、拒绝此方案、回滚当前文件）。`disabled` 用 `opacity: .4`。

文案用工程动作：新建任务、查看运行、批准并继续、拒绝、修改参数、仅查看命令、重试此步骤、从此处重新运行、查看变更、运行检查、回滚当前文件、接受并标记已验证。禁止「开始你的 AI 之旅」「智能提升效率」「一键生成」「AI 魔法」等营销句。

## 边框、圆角、阴影

少用边框。优先靠背景差、缩进、留白、活跃底、轻分隔。边框只用于 Diff 行、输入焦点、审批卡片左侧风险提示、终端边界、表单控件。

圆角：`--radius-sm: 4px; --radius-md: 6px; --radius-lg: 8px`。不用 16–24px 大圆角。

阴影极轻：`0 1px 2px rgba(46, 52, 54, 0.08)`。用于主工作区、浮层、审批区、需与画布分开的工具面板。无多层、发光或彩色阴影。

## 代码、日志与 Diff

不要让整页变黑。深色终端底只给 Shell 输出、原始日志、长命令结果；暖灰底给路径、短片段、配置、命令预览。

Diff 按审查工具语义：新增绿、删除暗红、上下文中性灰、文件名等宽、行号低对比。不要包装成「AI 结果卡片」。

终端默认摘要（命令、通过/失败计数、退出码），用户点「展开原始日志」后再给全文。

## 状态与审批

状态必须同时有文字和颜色，例如：`运行中 · 第 4/6 步`、`等待批准 · 修改 3 个文件`、`已完成 · 9 个测试通过`、`部分完成 · Lint 未执行`、`失败 · 命令退出码 1`。不允许只靠色点、图标、进度条或无解释的「成功」。

审批区说明：具体动作、影响的文件或资源、原因、是否改数据库 / 访问远程、能否撤回、批准后进入哪一步。按钮用工程动作（批准并继续、仅允许测试文件修改、仅查看命令、修改限制后重新规划、拒绝此方案、暂停任务）。

任务摘要条（如「修改 3 个文件 · 新增 1 个回归测试」+ 约束 + 主/次按钮）是工作区内容模块，不是 Toast。

## 对话

用户与助手均左对齐。用户浅底圆角气泡；助手无气泡，直接落在画布。工具 / 系统等宽浅底。Composer 浅色圆角输入面，focus 略加深边。Run 标题区用留白分区，不加硬分割线。

## Toast / 弹窗 / 表单

操作结果、API 失败、复制成功、暂不支持等非阻塞反馈用 Toast（`components/Toast.tsx` 的 `useToast()`），顶部居中浮层，约 4s，新条替换旧条。禁止页面内嵌 error 条、为提醒预留固定 layout 导致跳动。禁止 `window.alert` / `confirm` / `prompt`。

删除与危险确认用应用内模态：sm ~384px 确认，md 480px 设置，lg 560–800px 多分区。Backdrop `rgba(46, 52, 54, .45)`，无 blur。

表单标签次要色；输入白底、细边、圆角 4–6px；focus 用主色轮廓。密钥等宽。字段校验可留在字段旁；全局错误走 Toast。

图标统一 Lucide（`lib/icons.tsx` 的 `Icon*`）。小尺寸 ≤16px 用 `strokeWidth={2}` + `absoluteStrokeWidth`。品牌标（GitHub / GitLab）用官方资源。

## 动画

过渡 ≤ 150ms。禁止长动画与大面积 blur。状态切换避免 layout shift。

## 反模式

大面积蓝色品牌底、过大营销标题、过多高亮标签、大量圆角卡片、渐变、发光、拟人化 Agent 插画、装饰图标、用完整日志填满页面、只用颜色表达状态、把过程压成「Agent 正在思考」、把失败藏成普通通知、使用「智能 / 高效 / 下一代」、让用户看不到命令、文件和检查依据。

## 原则

过程优先、证据优先、人工可接管、工程化表达、安静克制、代码友好、状态明确、持续可追溯。最终目标是让开发者像使用 VS Code、GNOME 工具或终端一样，安静、清晰、可控地管理 Agent 执行。
