# Loop charter（自主循环章程）

适用于任何自动触发的代理循环（定时心跳、CI 事件）。分级准入：**L1 半自动**（人触发、代理执行）、
**L2 事件驱动安全车道**（定时 + 路径白名单）、**L3 issue→PR**（需「loop-safe」标签 + 验收命令的
issue 模板，暂未开放）。当前仅允许 L1 / L2。

## 硬性边界（违反任何一条即属事故）

1. **终点动作 = 开 PR**。永不 merge、永不打 tag、永不直接 push main（AGENTS.md 规则 5）。
2. **路径白名单**：循环只能改动白名单内路径。当前唯一批准车道（文档生命周期）：
   `docs/**`、`.agents/**`、`scripts/check_docs_lifecycle.sh` 的白名单注释。扩大白名单
   必须先以人工 PR 修改本文件。
3. **专用 worktree**：每次运行在独立 `git worktree`，禁止读写任何已检出的工作目录与
   未提交状态。
4. **预算**：单次运行上限 30 分钟 / 200 次工具调用；触顶立即停止并开 issue 附现场，
   不得「再试一次」。
5. **停止条件必须机器可判**：`scripts/check_docs_lifecycle.sh` 与
   `scripts/check_release_sync.sh` 全绿 + diff 不越白名单。无法机器判定的停下开 issue，
   不猜。
6. **永不进入**：`src/pool/` 参数、`src/adapter/wire/` 协议边界、生产调参、发版流程、
   数据库迁移内容（迁移文件的新增/修改一律人工）。
7. **可审计**：每次运行的报告（做了什么、diff 摘要、预算消耗、跳过了什么）写进 PR
   描述；中间产物进本地 `artifacts/`，不入库。

## 触发与升级

- 触发源：定时心跳或 CI 事件。每次触发视为独立任务，无跨运行记忆——交接只靠文件
  （PR 描述、issue、progress 类产物），不靠会话。
- 升级给人（任一即触发）：需要白名单外的改动、预算耗尽、门禁红且无法机械修复、
  需要 landed/promote 类裁决（改白名单属于此类）。

## 当前活跃循环（台账）

| 车道 | 载体 | 频率 | 预算 | 状态 |
|---|---|---|---|---|
| 文档生命周期巡检（broken/mangled→PR；landed/promote→issue） | A：本地持久化定时任务 | 每日 09:00 | ≤30min / ≤200 调用 | 试点中（2026-08-29 空跑验证：1s 绿、零动作、无痕收尾） |

**A→B 切换标准**（观察期 2026-08-29 起两周，至 2026-09-12）：无漏跑、PR 仅含机械修复、无误报 issue。满足后翻译为 GitHub scheduled workflow（载体 B，摆脱对单一机器的依赖），并在本表记录切换。

**判据证据源**：每次运行（含零动作）向本地 `artifacts/loop-docs-patrol.log` 追加一行「日期 + 结果 + 预算」；漏跑以该日志缺行核对，PR/issue 以仓库为准。日志属本地 artifacts，不入库。

## 与既有机制的关系

- 代码评审走 skill `review`（独立只读上下文）；循环开的 PR 同样适用。
- 本章程不覆盖发版（skill `release` 的人工批准硬停优先级更高）。
